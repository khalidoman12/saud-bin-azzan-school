# رصد الموهبة — مدرسة سعود بن عزان البوسعيدي (5–8)

## حالة النسخة الحالية

التطبيق جاهز للتجربة على خادم خاص، ويتطلب إنشاء حسابات المعلمين، وتهيئة رموز الأقسام، وتوفير استضافة وقاعدة بيانات دائمة قبل التشغيل المدرسي. لم يُنشر بعد على الإنترنت من هذا المستودع. **مستودع GitHub عام وGitHub Pages غير صالح لحفظ بيانات الطلبة.**

### ما يشمله التطبيق

- **9 مواد دراسية**، ولكل مادة 10 مؤشرات متخصصة وقائمة أنواع الموهبة، إضافة إلى **مسؤول مصادر التعلم** و**الأخصائي النفسي والاجتماعي**.
- بوابة **سجل تقييم الطلبة الموهوبين** تعرض الترشيحات للمخولين فقط، مع البحث والتصفية والطباعة وتصدير CSV المتوافق مع Excel.
- كل بوابة من **12 بوابة** لها رمز رباعي مستقل، بالإضافة إلى **حساب شخصي وكلمة مرور قوية لكل معلم**. لا يمكن استخدام الرمز المشترك وحده للوصول إلى قاعدة البيانات.
- يربط الخادم تلقائيًا كل ترشيح بهوية المعلم المصادق عليه؛ لا يثق بالاسم القادم من المتصفح.
- حفظ مسودة خاصة بكل معلم وقسم، والعودة إلى ترشيحاته السابقة وعرضها وطباعتها.
- رأي لجنة الموهوبين اختياري؛ يمكن للمراجع المخول إضافته لاحقًا مع الحفاظ على إجابات المعلم.
- تجزئة كلمات المرور والرموز مع Salt، جلسات HttpOnly وSameSite، فحص Origin، تحديد محاولات الدخول وقفل الحساب مؤقتًا، وصلاحيات خادم وقاعدة بيانات، وسجل تدقيق.
- أداة لإدارة الحسابات، ونسخ احتياطي متسق SQLite، وملفات نشر Docker مع HTTPS بواسطة Caddy.

> **تنبيه علمي:** المعايير للتعرف على مؤشرات الموهبة والترشيح الأولي، وليست اختبارات سيكومترية مقننة. لا يصدر النظام حكمًا نهائيًا من مجموع الإجابات وحده.

## التشغيل المحلي للتجربة

يتطلب Python 3.11 أو أحدث:

```bash
cd talent-system
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup_pins.py
python manage_users.py add --username teacher01 --name "معلم تجريبي" --scopes math
python manage_users.py add --username counselor01 --name "أخصائي مخول" --scopes counseling --registry --reviewer
python manage_users.py add --username registry01 --name "مسؤول سجل" --scopes resources --registry
TALENT_COOKIE_SECURE=false uvicorn server:app --host 127.0.0.1 --port 8088
```

ابدأ بـ http://127.0.0.1:8088 وافتح المادة بحساب المعلم الشخصي وكلمة مروره ورمز القسم من ملف الإعداد الخاص بك. لا تستخدم بيانات الطلبة الحقيقية أثناء التجربة المحلية غير المراجعة.

عند إضافة معلم يدرس أكثر من مادة، استخدم `--scopes math,science` مثلًا. لمراجعة الحسابات: `python manage_users.py list`. لتعطيل حساب: `python manage_users.py disable --username teacher01`. لتغيير كلمة المرور: `python manage_users.py reset-password --username teacher01`.

**أمثلة أسماء المستخدمين أعلاه توضيحية فقط؛ لا تُنشأ أي حسابات افتراضيًا أثناء نشر الكود.**

## النشر الآمن على خادم خاص

يتطلب النشر الفعلي خادم VPS أو خدمة استضافة توفر **قرصًا دائمًا** ومجالًا باسم المدرسة مع عنوان DNS صحيح وموافقة مؤسسية على تخزين بيانات الطلبة.

1. على الخادم الخاص، أنشئ مجلدًا واستنسخ المستودع وفرع المشروع بعد مراجعته. ادخل `talent-system/`.
2. انسخ `.env.example` إلى `.env` وعدّل `TALENT_DOMAIN` و`TALENT_EMAIL` لقيم صحيحة، ولا ترفع ملف `.env` إلى GitHub.
3. فعّل DNS نحو عنوان الخادم، وافتح المنفذين 80 و443 لتمكين شهادة HTTPS التلقائية. لا تنشر منفذ التطبيق الداخلي 8088.
4. شغّل `docker compose build`.
5. هيئ رموز الأقسام وحسابات المستخدمين على وحدة التخزين الدائمة **قبل إطلاق واجهة الموقع**:

```bash
docker compose run --rm --no-deps -it app python setup_pins.py
docker compose run --rm --no-deps -it app python manage_users.py add --username teacher01 --name "اسم المعلم الحقيقي" --scopes math
docker compose run --rm --no-deps -it app python manage_users.py add --username counselor01 --name "اسم الأخصائي المخول" --scopes counseling --registry --reviewer
```

6. شغّل `docker compose up -d` وتحقق من شهادة TLS، وصفحة الموقع، وعدم فتح السجل إلا لحساب مخول.
7. اختبر على بيانات وهمية، ثم أجرِ مراجعة تنظيمية وأمنية قبل السماح بإدخال أسماء طلاب حقيقية.

### الأرقام الرباعية

الرموز السابقة التي اختيرت للقسم **غير مضمنة في هذه الملفات**. يتطلب `setup_pins.py` إدخال رمز لكل قسم تفاعليًا؛ ويُخزَّن على الخادم مشتق مملح من الرمز فقط. مشاركة الأرقام نفسها مع المعلمين يجب أن تكون عبر قناة داخلية معتمدة، وبما يتناسب مع نطاق كل مادة. تُعد الأرقام المعروضة في محادثة سابقة مبدئية ويُفضّل استبدالها قبل التشغيل الفعلي.

### النسخ الاحتياطية واستعادة الخدمة

يمكن تنفيذ:

```bash
docker compose exec app python tools/backup.py /data/backups
```

ينشئ ذلك ملف SQLite متسقًا في المجلد الدائم الخاص بالتطبيق. **يجب تشفير النسخ الاحتياطية ونقلها إلى موقع منفصل محمي** ووضع جدول دوري لها واختبار الاستعادة بانتظام، لأن تخزين النسخ على القرص نفسه لا يحمي من فقدان الخادم. قبل إعادة الاستعادة أوقف التطبيق، واحفظ نسخة من الحالة الحالية، وتحقق من سلامة النسخة المراد استرجاعها.

## حدود الاستخدام والاعتماد

- لا توجد حتى الآن منصة استضافة متصلة في هذه المحادثة؛ رفع الكود إلى GitHub لا يساوي نشر موقع عامل على الإنترنت.
- لا تضع قاعدة البيانات أو نسخها أو كلمات المرور أو رموز الأقسام في المستودع العام.
- التطبيق الحالي يدعم الأدلة **كنص وصفي**، لا رفع الملفات. رفع الصور ومرفقات الطالب يتطلب مخزنًا خاصًا، وتحققًا من الملفات، وصلاحيات دقيقة.
- تصدير البيانات متاح للمخولين، وهو إجراء حساس يجب استخدامه وفق سياسة المؤسسة.
- رقم الطالب المدرسي الداخلي غير مطبق بعد؛ تقرير العدد الفريد حسب الاسم والصف **تقديري**. يجب إضافة معرّف فريد لاحقًا لتفادي احتساب الأسماء المتشابهة خطأً.
- لا يدّعي المشروع إتمام تدقيق أمني خارجي أو مصادقة متعددة العوامل أو اعتماد مؤسسي أو امتثال قانوني تلقائي. قبل التشغيل الفعلي يلزم استكمال مراجعة حماية بيانات القاصرين والنسخ الاحتياطي وسياسات الصلاحيات والسجلات.
- خادم `uvicorn` يستخدم عاملًا واحدًا مع SQLite. لإنتاج عالي الحمل يُفضل الانتقال إلى PostgreSQL وقيود محاولات دخول مشتركة مركزيًا.
- حسابات المراجعة ممنوحة بحسب امتيازات الحساب الشخصية، وليس لمجرد معرفة رمز قسم الأخصائي.
- في كل صفحة رسمية: إعداد الأخصائيين النفسيين والاجتماعيين أ. خالد المشايخي، أ. حمد الشماخي، أ. شهاب الهاشمي، أ. خميس الساعدي.
